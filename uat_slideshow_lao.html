Introduction

1. ວັດຖຸປະສົງຂອງການທົດສອບລະບົບ

ເປົ້າໝາຍການທົດສອບລະບົບຕົ້ນແບບ

  • ຄວາມສົມເຫດສົມຜົນ (Process Logic): ກວດສອບຄວາມຖືກຕ້ອງຂອງຂັ້ນຕອນການກົດສະຫຼັບໜ້າຈໍ (Screen Flow) ໃນແຕ່ລະ Use Case
  • ... ຄວາມງ່າຍໃນການນຳໃຊ້ (Usability & Copy): ກວດສອບຄຳອະທິບາຍ ຂະໜາດປຸ່ມກົດ ພາສາທີ່ລະບຸ ແລະ ຂໍ້ມູນສະແດງຜົນໃນຕາຕະລາງຫຼັງບ້ານ
  • ການເກັບກຳຂໍ້ມູນຄຳຄິດເຫັນ (Feedback): ຮວບຮວມຂໍ້ຕິດຂັດເພື່ອຈັດສົ່ງຕໍ່ເປັນຄວາມຕ້ອງການທີ່ສົມບູນໃຫ້ທີມຂຽນໂຄ້ດລະບົບຈິງຕໍ່ໄປ

ໂປດເຂົ້າໃຈ: ນີ້ຄືລະບົບຕົ້ນແບບ (Prototype)

ລະບົບທັງໝົດເຮັດໜ້າທີ່ຈຳລອງໜ້າຕາ ແລະ ການເຮັດວຽກຈຳລອງເທົ່ານັ້ນ ຂໍ້ມູນທີ່ມີການບັນທຶກ ຫຼື ກອກລົງໃນເວັບທັງໝົດຄືຂໍ້ມູນຕົວຢ່າງ ບໍ່ສົ່ງຜົນກະທົບຕໍ່ຖານຂໍ້ມູນລະບົບຈິງໃດໆທັງສິ້ນ ບໍ່ຕ້ອງກັງວົນວ່າລະບົບຈະເສຍຫາຍ

ໄລຍະເວລາທົດສອບລະບົບຕົ້ນແບບ

ພວກເຮົາຈຳກັດເປົ້າໝາຍເວລາການທົດສອບຂອງທຸກກຸ່ມໃຫ້ຢູ່ພາຍໃນ 90 ນາທີ ເພື່ອຄວາມກະຊັບ ແລະ ບໍ່ດຶງເວລາການເຮັດວຽກຫຼັກຂອງຜູ້ຮ່ວມທົດສອບລະບົບຕົ້ນແບບທຸກຄົນ

How to Test

3. ວິທີຄວບຄຸມ ແລະ ທົດລອງລັນສະຖານະການ (Harness Bar)

ການໃຊ້ Scenario Harness Bar (ແຖບດ້ານເທິງ)

ຢູ່ຫົວມຸມເທິງຂອງທຸກໜ້າຈໍຕົ້ນແບບຈະມີແຖບຕົວເລືອກຈຳລອງສາກເຮັດໜ້າທີ່ຄວບຄຸມສະຖານະໜ້າເວັບເພື່ອທົດສອບເຄສຕ່າງໆ:

  • Main Flow / Happy Path: ເລີ່ມຕົ້ນດ້ວຍເຄສປົກກະຕິ ເຮັດວຽກຮາບຮື່ນ ແລະ ສິ້ນສຸດສົມບູນແບບ
  • Alternative Flow (AF-xx): ຈຳລອງສະຖານະການເກີດເລື່ອງອື່ນໆ ເຊັ່ນ ອັບໂຫລດໄຟລ໌ຜິດປະເພດ, ກົດຖອຍກັບ ຫຼື ອິນເຕີເນັດຂາດຫາຍກາງຄັນ

ໜ້າຈໍສະແດງຜົນສະຖານະ Pending

ຫາກໜ້າຈໍດັ່ງກ່າວລະບຸຄຳວ່າ Pending ຫຼື ປຸ່ມກົດສະແດງສະຖານະສີຈາງບໍ່ສາມາດຄລິກເຊື່ອມໂຍງໜ້າຕ່າງໄດ້:

  • ໝາຍເຖິງ Use Case ນັ້ນບໍ່ໄດ້ຢູ່ໃນການພັດທະນາຂອງຕົວຈຳລອງຕົ້ນແບບນີ້
  • ຄຳແນະນຳ: ບໍ່ຕ້ອງຕົກໃຈ ໃຫ້ເປີດໄຟລ໌ Excel ໃນແຖວ Use Case ນັ້ນໆ ແລະ ເລືອກຜົນການທົດສອບເປັນຊ່ອງ N-T (Not Tested) ທັນທີ ເພື່ອຂ້າມໄປເຮັດຂໍ້ຖັດໄປ
Feedback Rubric

4. ການກອກປະເມີນລົງຕາຕະລາງ Excel (Feedback Sheet)

Result (ຜົນລັບ)

ປ້ອນຜົນລັບການເຮັດວຽກ:
Pass = ເຮັດວຽກໄດ້ຮາບຮື່ນ
Fail = ມີບັນຫາ ຂັ້ນຕອນບໍ່ກົງ ຫຼື ຈຸດສັບສົນ
N-T = ໜ້ານັ້ນກົດທົດສອບບໍ່ໄດ້ (Not Tested)

Ease (ລະດັບຄວາມງ່າຍ)

... ປະເມີນຄວາມເພິ່ງພໍໃຈການຕອບສະໜອງ ຄະແນນຕັ້ງແຕ່ 1 ເຖິງ 5:
1 = ຊອກຫາຍາກຫຼາຍ ສັບສົນ ຊອກປຸ່ມບໍ່ເຫັນ
5 = ໃຊ້ງານງ່າຍ ເຂົ້າໃຈຂັ້ນຕອນທັນທີ

Remark (ຄຳຄິດເຫັນ)

ຂຽນຂໍ້ຄວາມລະບຸສິ່ງທີ່ເກີດຂຶ້ນ ເຊັ່ນ ປຸ່ມບໍ່ເຫັນເດັ່ນ, ຄຳແປພາສາລາວສັບສົນ, ຫຼື ຕ້ອງການຟີວເພີ່ມເຕີມໃນລະບົບຈິງ

ຕົວຢ່າງຕາຕະລາງບັນທຶກຜົນການທົດສອບ (UAT Feedback Spreadsheet Example)

  • ຕອບຄຳຖາມປາຍເປີດ 4 ຂໍ້ຫຼັກ (ສິ່ງທີ່ທ່ານມັກ, ຂໍ້ຄວນປັບປຸງ, ສິ່ງກີດຂວາງ, ຂໍ້ສະເໜີແນະອື່ນໆ)
  • ບັນທຶກໄຟລ໌ (Save) ກ່ອນຈະທຳການປິດໂປຣແກຣມ

ກວດສອບຄວາມຄົບຖ້ວນ

  • ກວດສອບຊ່ອງ Result (Pass/Fail/N-T) ແລະ Ease (1-5) ຄົບທຸກຫົວຂໍ້ທີ່ທົດສອບ
  • ພິມລະບຸຂໍ້ຕິດຂັດ ຫຼື ຂໍ້ສະເໜີແນະລົງໃນຊ່ອງ Remark ໃນແຖວທີ່ມີບັນຫາໃຫ້ຮຽບຮ້ອຍ
  • ບັນທຶກ ແລະ ປິດໂປຣແກຣມໃຫ້ຮຽບຮ້ອຍ ໂດຍບໍ່ຕ້ອງລະບຸວ່າຈະຈັດສົ່ງໄປບ່ອນໃດ ຫຼື ທາງແຊັດກຸ່ມໃດ ເນື່ອງຈາກການປະຕິບັດຕົວຈິງຈະມີການລວບລວມໄຟລ໌ດ້ວຍວິທີອື່ນແຍກຕ່າງຫາກຢູ່ແລ້ວ
Wrap-up & Next Steps

63. ເສັດສິ້ນການທົບທວນລະບົບຕົ້ນແບບ & ຂັ້ນຕອນຖັດໄປ

ຂັ້ນຕອນຖັດໄປຂອງໂຄງການ (Next Steps)

  • ຮວບຮວມ ແລະ ວິເຄາະຂໍ້ມູນປ້ອນກັບ (Consolidate Feedback)
    ທີມງານພັດທະນາຈະຮວບຮວມຄຳແນະນຳ ແລະ ບັນຫາການນຳໃຊ້ຈາກຜູ້ຮ່ວມທົບທວນທຸກຄົນເພື່ອຈັດກຸ່ມຄວາມຕ້ອງການ
  • ຈັດລໍາດັບຄວາມສໍາຄັນເພື່ອການພັດທະນາຈິງ (Prioritization)
    ຈຳແນກຟັງຊັນທີ່ເປັນຫົວໃຈຫຼັກ ແລະ ປະເດັນການອອກແບບເພື່ອໄປພັດທະນາໂຄງສ້າງລະບົບໃຫ້ສົມບູນຂຶ້ນ
  • ເລີ່ມຂະບວນການພັດທະນາຊອບແວຈິງ (System Development)
    ນຳຜົນການທົບທວນ ແລະ ແບບຈຳລອງທີ່ຜ່ານການປັບປຸງໄປເປັນພິມຂຽວ (Blueprint) ໃນການຂຽນໂຄດລະບົບຈິງຕໍ່ໄປ

ຂອບໃຈຜູ້ຮ່ວມທົດສອບ (Thank You)

ຂໍຂອບໃຈອາຈານ, ຜູ້ຕາງໜ້າວິທະຍາໄລ, ແອດມິນລະບົບ ແລະ ຜູ້ຮ່ວມໂຄງການທຸກທ່ານເປັນຢ່າງສູງທີ່ສະຫຼະເວລາອັນມີຄ່າໃນການຮ່ວມທົບທວນລະບົບຕົ້ນແບບຈຳລອງໃນມື້ນີ້. ຄຳຄິດເຫັນຂອງທຸກທ່ານມີຄຸນຄ່າຍິ່ງຕໍ່ການຮ່ວມພັດທະນາແພລດຟອມການຈັດການຮຽນຮູ້ອາຊີວະສຶກສາ (SkillsLao TVET Platform) ໃຫ້ຕອບໂຈດຜູ້ໃຊ້ງານຈິງ ແລະ ກ້າວໜ້າຢ່າງໝັ້ນຄົງ.
